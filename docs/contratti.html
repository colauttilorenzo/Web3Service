Contratti, token e NFT

Qualsiasi contratto, chiamato per nome con parametri JSON.

Con l’ABI di un contratto (il JSON che il compilatore produce insieme al bytecode) e il suo indirizzo, getContract restituisce un oggetto che elenca tutti i metodi e li chiama per nome. I parametri sono un oggetto JSON con i nomi dell’ABI: non serve codificare nulla, né conoscere i tipi Solidity.

app/api/token/route.ts
import { web3 } from '@/lib/web3';
import tokenAbi from '@/lib/token-abi.json'; // l'ABI del contratto, come lo esporta il compilatore

const token = web3.getContract(tokenAbi, process.env.TOKEN_ADDRESS!);

// GET: cosa offre il contratto. Ogni metodo dice se legge o scrive e quali parametri vuole.
export async function GET() {
  return Response.json({ standards: token.standards, owner: await token.owner(), methods: token.methods });
}

// POST { "method": "transfer", "parameters": { "to": "0x...", "amount": "1000" } }
export async function POST(request: Request) {
  const { method, parameters } = await request.json();
  return Response.json(await token.call(method, parameters)); // lettura: il valore; scrittura: la transazione
}
app.js
// tokenAbi: l'ABI del contratto, per esempio caricato con fetch('token-abi.json').
const token = service.getContract(tokenAbi, '0x...');

for (const method of token.methods) {
  console.log(method.name, method.kind, method.parameters); // es. transfer write { to: 'string', amount: 'number' }
}

const balance = await token.call('balanceOf', { account: '0x...' });          // lettura, gratuita
const transfer = await token.call('transfer', { to: '0x...', amount: '1000' }); // il wallet chiede la firma
console.log(balance, transfer.tx.transactionHash);
src/routes/notarization.ts

Program.cs
var tokenAbi = await File.ReadAllTextAsync("token-abi.json");
var token = app.Services.GetRequiredService<Web3Service>().GetContract(tokenAbi, app.Configuration["Web3:Token"]!);

app.MapGet("/api/token", async () => Results.Ok(new { token.Standards, Owner = await token.OwnerAsync(), token.Methods }));

// POST /api/token/transfer { "to": "0x...", "amount": "1000" }
app.MapPost("/api/token/{method}", async (string method, JsonObject parameters) =>
    Results.Ok(await token.CallAsync(method, parameters))); // lettura: il valore; scrittura: la transazione

Leggere i metodi

methods descrive ogni funzione del contratto. kind dice cosa succede chiamandola, parameters cosa passare:

kindCosa faCostocall restituisce
readLegge dati (view, pure)Gratuita, nessuna firmaIl valore: un solo output così com’è, più output in un array
writeModifica lo stato del contrattoTransazione firmata, paga gasLa transazione (ITransaction) quando è in un blocco
payableCome write, e può ricevere moneta nativaGas più options.valueLa transazione
Tipo in parametersTipi SolidityCosa passare
numberuint*, int*Un numero intero o una stringa decimale; stringa oltre 253. I risultati sono sempre stringhe.
stringstring, address, bytes*Testo; indirizzi e bytes come 0x… (maiuscole o minuscole)
booleanbooltrue o false
arrayT[], T[n]Un array di valori del tipo dell’elemento
objecttuple (struct)Un oggetto con un campo per ogni elemento della struct

I parametri senza nome nell’ABI (per esempio i getter pubblici generati da Solidity) si chiamano arg0, arg1 e così via. Se più funzioni hanno lo stesso nome, la libreria sceglie quella con gli stessi nomi di parametri; in alternativa passa la firma, es. 'safeTransferFrom(address,address,uint256)'. Un parametro mancante, in più o del tipo sbagliato restituisce INVALID_ARGUMENT prima di contattare il nodo.

Suggerimento

read esegue anche un metodo di scrittura come simulazione gratuita, senza transazione e con mittente l’indirizzo zero. encode restituisce invece i dati della chiamata, per farla firmare altrove (per esempio da un multisig).

Standard ERC

standards (e il metodo statico Web3Service.detectStandards(abi)) riconosce gli standard dall’ABI: uno standard è presente quando l’ABI contiene tutte le sue funzioni.

StandardCosa indica
ERC-20Token fungibile (monete, punti)
ERC-721, ERC-721 Metadata, ERC-721 EnumerableNFT: ogni token è unico, con URI dei metadati ed elenco dei token
ERC-1155, ERC-1155 Metadata URIMulti-token: più tipi di token, fungibili o unici, nello stesso contratto
ERC-165Il contratto dichiara le interfacce che supporta
ERC-173Proprietario del contratto (owner(), transferOwnership)
ERC-2981Royalty sulle vendite degli NFT

Creare NFT e leggere i token

mintNft funziona sui contratti ERC-721 ed ERC-1155 che hanno una funzione safeMint, mint o mintTo: i nomi dei parametri scelgono quale chiamare, e il risultato contiene gli ID dei token creati, letti dagli eventi del contratto. getTokenInfo legge nome, simbolo, decimali e offerta totale; con l’ID di un NFT anche proprietario e URI dei metadati. Legge solo le funzioni presenti nell’ABI.

app/api/nft/route.ts
import { web3 } from '@/lib/web3';
import nftAbi from '@/lib/nft-abi.json';

const nft = web3.getContract(nftAbi, process.env.NFT_ADDRESS!);

// POST { "to": "0x...", "uri": "ipfs://..." }: i nomi dei parametri scelgono la funzione di mint.
export async function POST(request: Request) {
  const { tokenIds, transaction } = await nft.mintNft(await request.json());
  return Response.json({ tokenId: tokenIds[0], token: await nft.getTokenInfo(tokenIds[0]), transaction });
}
app.js
const nft = service.getContract(nftAbi, '0x...');

// Il wallet dell'utente firma; tokenIds contiene gli ID creati.
const { tokenIds } = await nft.mintNft({ to: account, uri: 'ipfs://bafy...' });
const info = await nft.getTokenInfo(tokenIds[0]);
console.log(info.name, info.owner, info.tokenURI);
src/routes/notarization.ts

Program.cs
var nftAbi = await File.ReadAllTextAsync("nft-abi.json");
var nft = app.Services.GetRequiredService<Web3Service>().GetContract(nftAbi, app.Configuration["Web3:Nft"]!);

// POST /api/nft { "to": "0x...", "uri": "ipfs://..." }
app.MapPost("/api/nft", async (JsonObject parameters) =>
{

    return Results.Ok(new { TokenId = minted.TokenIds[0], minted.Transaction.Tx!.TransactionHash });
});

app.MapGet("/api/nft/{id}", async (string id) => Results.Ok(await nft.GetTokenInfoAsync(id)));
Nota

Chi chiama mintNft deve avere il permesso di creare token: molti contratti lo riservano al proprietario. Se il contratto rifiuta ottieni TRANSACTION_REVERTED; se non è un NFT, NOT_SUPPORTED.

Leggere una transazione

getTransaction(hash, abi?) legge una transazione qualsiasi, anche in attesa (pending: true). Una volta inclusa aggiunge ricevuta, orario del blocco e costo. Con l’ABI decodifica anche la funzione chiamata e i suoi argomenti; contract.getTransaction(hash) usa l’ABI del contratto.

app/api/transactions/[hash]/details/route.ts
import { web3 } from '@/lib/web3';
import tokenAbi from '@/lib/token-abi.json';

// Con l'ABI la risposta dice anche quale funzione è stata chiamata e con quali argomenti.
export async function GET(_request: Request, { params }: { params: Promise<{ hash: string }> }) {
  const details = await web3.getTransaction((await params).hash, tokenAbi);
  return Response.json(details); // details.method: { name: 'transfer', parameters: { to, amount } }
}
app.js
const details = await service.getTransaction(transactionHash, tokenAbi);
if (details.pending) console.log('In attesa di conferma');
else console.log(details.method?.name, details.method?.parameters, details.receipt.status);
src/routes/notarization.ts
app.get<{ Params: { hash: string } }>('/transactions/:hash/details', async request =>
