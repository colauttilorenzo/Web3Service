Firma delle transazioni

Chiave privata, mnemonic o wallet del browser.

Le letture non richiedono credenziali. Per mint e deploy scegli uno dei tre signer: sul server una chiave privata o un mnemonic, nel browser il wallet dell’utente.

lib/web3.ts
import 'server-only';
import { Web3Service } from '@certifie/web3-service';

const provider = { rpcURI: process.env.RPC_URL!, chainId: process.env.CHAIN_ID };

// Sul server: chiave privata…
export const web3 = new Web3Service(provider, { signer: { privateKey: process.env.PRIVATE_KEY! } });

// …oppure mnemonic, derivato in m/44'/60'/0'/0/1 (anche { mnemonic: { phrase, password } })
export const web3FromMnemonic = new Web3Service(provider, {
  signer: { mnemonic: process.env.MNEMONIC!, walletIndex: 1 },
});
lib/browser-web3.ts
import { Web3Service, type Eip1193Provider } from '@certifie/web3-service';

// Nel browser firma il wallet dell'utente: chiamala solo da componenti 'use client'.
export function browserWeb3(): Web3Service | null {
  const wallet = (window as { ethereum?: Eip1193Provider }).ethereum;
  if (!wallet) return null;
  const provider = { rpcURI: process.env.NEXT_PUBLIC_RPC_URL!, chainId: process.env.NEXT_PUBLIC_CHAIN_ID };
  return new Web3Service(provider, { signer: { wallet, switchChain: true } });
}

Attenzione

Non mettere mai una chiave privata o un mnemonic nel codice del frontend: chiunque apra la pagina può leggerli. Nel browser usa wallet, oppure chiama un endpoint del tuo backend.

Wallet del browser (EIP-1193)

Con signer: { wallet } il wallet firma e invia la transazione, mentre stima del gas, attesa del blocco e ricevuta passano dal nodo rpcURI. Il risultato ha quindi la stessa forma del backend.

  1. La libreria chiede l’account con eth_requestAccounts.
  2. Se il wallet è su un’altra rete chiede wallet_switchEthereumChain. Se la rete è sconosciuta la aggiunge con wallet_addEthereumChain usando chainName, nativeCurrency, rpcPublicURI/rpcURI e blockExplorerURI. Con switchChain: false restituisce invece CHAIN_ID_MISMATCH.
  3. Stima il gas tramite il nodo e lascia al wallet le commissioni, salvo un gasPrice esplicito.
  4. Invia con eth_sendTransaction. Se l’utente annulla ottieni USER_REJECTED e nulla viene inviato.

Fastify, Express e .NET non hanno un wallet: nelle loro schede l’esempio gestisce l’errore equivalente lato server, cioè un invio non confermato.

app/notarize/sign-button.tsx
'use client';

import { useState } from 'react';
import { Web3Error, type NotarizationDocument } from '@certifie/web3-service';
import { browserWeb3 } from '@/lib/browser-web3';
import { notarizerAbi } from '@/lib/notarizer-abi';

export function SignButton({ document }: { document: NotarizationDocument }) {
  const [message, setMessage] = useState<string>();

  async function sign() {
    try {
      await browserWeb3()?.mint(notarizerAbi, process.env.NEXT_PUBLIC_CONTRACT_ADDRESS!, document);
    } catch (error) {
      if (error instanceof Web3Error && error.code === 'USER_REJECTED') setMessage('Firma annullata');
      else throw error;
    }
  }

  return <><button onClick={sign}>Firma con il wallet</button>{message && <p role="status">{message}</p>}</>;
}

src/routes/notarization.ts
import { Web3Error, type NotarizationDocument } from '@certifie/web3-service';

// Sul server nessun utente firma: l'errore da gestire è l'invio non confermato.
app.post<{ Body: NotarizationDocument }>('/notarize', async (request, reply) => {
  try {
    return await app.web3.mint(notarizerAbi, app.contractAddress, request.body);
  } catch (error) {
    if (error instanceof Web3Error && error.code === 'TRANSACTION_SUBMISSION_FAILED') {
      return reply.status(202).send({ pending: error.transactionHash }); // controlla la ricevuta prima di riprovare
    }
    throw error;
  }
});

Nonce e scritture concorrenti

Le scritture della stessa istanza vengono eseguite una alla volta, così ricevono nonce distinti. Nel backend crea quindi un’unica istanza condivisa. Se più processi usano lo stesso account devi coordinare i nonce, per esempio passando nonce nelle opzioni o usando un account per processo.
