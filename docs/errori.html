API

Errori

Web3Error, codici e gestione nelle API.

Tutti gli errori sono istanze di Web3Error con code, message ed eventuale transactionHash. La causa originale è in cause; toJSON() la esclude per non serializzare URL con credenziali o transazioni firmate. In .NET l’equivalente è Web3Exception con Code, TransactionHash, InnerException e ToInfo().

Un’operazione che la blockchain del provider non offre, come deploy su Bitcoin, restituisce NotImplementedError: una sottoclasse di Web3Error con codice NOT_IMPLEMENTED. In .NET è la System.NotImplementedException standard.

CodiceSignificato
INVALID_ARGUMENTConfigurazione o parametro non valido
SIGNER_REQUIREDCredenziali mancanti per una scrittura, o il wallet non ha fornito un account
PROVIDER_UNAVAILABLENessun endpoint raggiungibile
CHAIN_ID_MISMATCHIl nodo o il wallet sono su un’altra rete
METHOD_NOT_FOUNDMetodo assente dall’ABI
NOT_SUPPORTEDIl contratto non offre la funzione richiesta, es. mintNft su un contratto che non è un NFT
NOT_IMPLEMENTEDLa blockchain del provider non offre l’operazione, es. deploy su Bitcoin (NotImplementedError; NotImplementedException in .NET)
RPC_ERRORChiamata, stima o firma fallita; dettagli in cause
TRANSACTION_NOT_FOUNDTransazione sconosciuta o non ancora inclusa
TOKEN_NOT_FOUNDIl token richiesto a getTokenInfo non esiste
TRANSACTION_REVERTEDInclusa con status: "0", oppure su Algorand rifiutata dalla simulazione prima dell’invio
TRANSACTION_SUBMISSION_FAILEDInvio fallito o conferma non arrivata: controlla transactionHash prima di riprovare
RECEIPT_DETAILS_FAILEDConfermata, ma arricchimento fallito: recuperala tramite hash
USER_REJECTEDL’utente ha annullato nel wallet del browser
WALLET_ERRORIl wallet del browser ha restituito un errore
UNSAFE_INTEGERUn provider personalizzato ha restituito un number non sicuro

Stati HTTP

Gli esempi backend usano questa funzione per rispondere con uno stato coerente. Nel browser i codici diventano invece messaggi per l’utente.

lib/http-status.ts
import type { Web3Error } from '@certifie/web3-service';

/** Traduce i codici della libreria in stati HTTP per le API del backend. */
export function httpStatus(error: Web3Error): number {
  switch (error.code) {
    case 'INVALID_ARGUMENT':
    case 'METHOD_NOT_FOUND':
      return 400;
    case 'TRANSACTION_NOT_FOUND':
    case 'TOKEN_NOT_FOUND':
      return 404;
    case 'TRANSACTION_REVERTED':
      return 409;
    case 'NOT_SUPPORTED':
      return 422;
    case 'NOT_IMPLEMENTED':
      return 501;
    case 'PROVIDER_UNAVAILABLE':
    case 'CHAIN_ID_MISMATCH':
      return 503;
    case 'TRANSACTION_SUBMISSION_FAILED':
      return 504;
    default:
      return 502;
  }
}
app/api/notarize/route.ts
import { Web3Error } from '@certifie/web3-service';
import { contractAddress, web3 } from '@/lib/web3';
import { notarizerAbi } from '@/lib/notarizer-abi';
import { httpStatus } from '@/lib/http-status';

export async function POST(request: Request) {
  try {
    return Response.json(await web3.mint(notarizerAbi, contractAddress, await request.json()));
  } catch (error) {
    if (error instanceof Web3Error) return Response.json(error.toJSON(), { status: httpStatus(error) });
    throw error;
  }
}
app.js
// Nel browser non ci sono stati HTTP: traduci i codici in messaggi per l'utente.
const messages = {
  USER_REJECTED: 'Firma annullata.',
  SIGNER_REQUIRED: 'Collega un wallet per continuare.',
  CHAIN_ID_MISMATCH: 'Passa alla rete Polygon Amoy nel wallet.',
  TRANSACTION_REVERTED: 'Il contratto ha rifiutato la transazione.',
};

function messageFor(error) {
  return error instanceof Web3Error ? messages[error.code] ?? error.message : String(error);
}

  return reply.send(error);

import type { ErrorRequestHandler } from 'express';
import { Web3Error } from '@certifie/web3-service';
import { httpStatus } from './http-status.js';

const web3Errors: ErrorRequestHandler = (error, _req, res, next) => {
  if (error instanceof Web3Error) return void res.status(httpStatus(error)).json(error.toJSON());
  next(error);
};
app.use(web3Errors); // dopo le rotte
Web3ExceptionHandler.cs
using Microsoft.AspNetCore.Diagnostics;

// Registrazione: builder.Services.AddExceptionHandler<Web3ExceptionHandler>(); e app.UseExceptionHandler(_ => { });
sealed class Web3ExceptionHandler : IExceptionHandler
{
    public async ValueTask<bool> TryHandleAsync(HttpContext context, Exception exception, CancellationToken token)
    {
        var info = exception switch
        {
            Web3Exception error => error.ToInfo(),
            NotImplementedException => new Web3ErrorInfo { Code = "NOT_IMPLEMENTED", Message = exception.Message },
            _ => null,
        };
        if (info is null) return false;
        context.Response.StatusCode = StatusFor(info.Code);
        await context.Response.WriteAsJsonAsync(info, token);
        return true;
    }

    static int StatusFor(string code) => code switch
    {
        "INVALID_ARGUMENT" or "METHOD_NOT_FOUND" => 400,
        "TRANSACTION_NOT_FOUND" or "TOKEN_NOT_FOUND" => 404,
        "TRANSACTION_REVERTED" => 409,
        "NOT_SUPPORTED" => 422,
        "NOT_IMPLEMENTED" => 501,
        "PROVIDER_UNAVAILABLE" or "CHAIN_ID_MISMATCH" => 503,
        "TRANSACTION_SUBMISSION_FAILED" => 504,
        _ => 502,
    };
}
Attenzione

Dopo TRANSACTION_SUBMISSION_FAILED non inviare subito una nuova transazione: la prima potrebbe essere ancora in attesa. Controlla prima getTransactionReceipt(error.transactionHash).
