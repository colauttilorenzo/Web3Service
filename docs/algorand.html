Blockchain

Algorand

Applicazioni ARC-4, Algorand Standard Asset e notarizzazione tramite un nodo algod.

Con un IAvmProvider lo stesso Web3Service lavora su Algorand: distribuisce applicazioni, notarizza con mint, chiama i metodi ARC-4 per nome, crea token (ASA) e legge transazioni. Parla con un nodo algod via REST, per esempio i nodi pubblici di Nodely o AlgoKit LocalNet, e restituisce lo stesso JSON delle reti EVM. In .NET l’implementazione è nativa e non richiede altri SDK.

Configurazione

Esempio
import { Web3Service, type IAvmProvider } from '@certifie/web3-service';

const testnet: IAvmProvider = {
  kind: 'avm',                                     // sceglie Algorand
  rpcURI: 'https://testnet-api.algonode.cloud',    // nodo algod
  rpcPublicURI: 'https://algod-fallback.example',  // fallback, opzionale
  indexerURI: 'https://testnet-idx.algonode.cloud', // opzionale: transazioni che algod non conserva più
  chainId: 'testnet-v1.0',                         // genesis ID, verificato a ogni operazione
  chainName: 'Algorand TestNet',
  blockExplorerURI: 'https://lora.algokit.io/testnet',
};

export const algorand = new Web3Service(testnet, { signer: { mnemonic: process.env.ALGORAND_MNEMONIC! } });
algorand.provider.nativeCurrency; // { name: 'Algo', symbol: 'ALGO', decimals: 6 }
Esempio
var algorand = new Web3Service(new AvmProvider
{
    RpcURI = "https://testnet-api.algonode.cloud",     // nodo algod
    RpcPublicURI = "https://algod-fallback.example",   // fallback, opzionale
    IndexerURI = "https://testnet-idx.algonode.cloud",  // opzionale: transazioni che algod non conserva più
    ChainId = "testnet-v1.0",                           // genesis ID, verificato a ogni operazione
    ChainName = "Algorand TestNet",
}, new Web3ServiceOptions { Mnemonic = builder.Configuration["Algorand:Mnemonic"] });

Console.WriteLine(algorand.Provider.Symbol); // "ALGO"

Firma

Le opzioni sono le stesse delle reti EVM, con il formato delle chiavi di Algorand. Gli account Algorand non derivano da un percorso, quindi walletIndex non si usa.

SignerFormatoDove
mnemonicLe 25 parole dell’account AlgorandBackend
privateKeySeed Ed25519 di 32 byte in esadecimale 0x…, oppure la secret key di 64 byte in base64 (account.sk di algosdk)Backend
walletUn IAvmWallet: { address, signTransactions }, per esempio da @txnlab/use-walletBrowser, solo TypeScript
Esempio
import { useWallet } from '@txnlab/use-wallet-react';
import { Web3Service } from '@certifie/web3-service';

// Nel browser firma il wallet dell'utente (Pera, Defly, Lute…): la chiave non arriva mai alla pagina.
const { activeAddress, signTransactions } = useWallet();
const web3 = new Web3Service(testnet, { signer: { wallet: { address: activeAddress!, signTransactions } } });
Esempio
// In .NET firma una chiave del backend: le 25 parole…
var web3 = new Web3Service(provider, new Web3ServiceOptions { Mnemonic = configuration["Algorand:Mnemonic"] });

// …oppure il seed di 32 byte in esadecimale, come lo restituisce AlgorandWallets.GetWallet(mnemonic).PrivateKey
var fromSeed = new Web3Service(provider, new Web3ServiceOptions { PrivateKey = configuration["Algorand:PrivateKey"] });

Per creare un account usa AlgorandWallets; vedi Metodi statici. Un account nuovo va finanziato con almeno 0,1 ALGO (il saldo minimo) più le commissioni.

Deploy

L’ABI è la descrizione dell’applicazione in JSON: ARC-56 (generata da Algorand Python, TEALScript e AlgoKit), ARC-32 o ARC-4. Con bytecode vuoto i programmi arrivano dalla descrizione ARC-56: compilati (byteCode) oppure sorgente TEAL (source), compilata dal nodo. In alternativa passa i programmi { approval, clear } in base64, in esadecimale 0x… o come sorgente TEAL.

Esempio
import notarizer from './Notarizer.arc56.json' with { type: 'json' };

// Gli argomenti vanno al metodo di creazione (qui create(string)void).
// value finanzia il conto dell'applicazione dopo la creazione, es. per le box che salverà: 0,2 ALGO in microAlgo.
const deployed = await algorand.deploy(notarizer, '', ['CERTIFIE'], undefined, { value: '200000' });
const appId = deployed.tx!.contractAddress!; // ID dell'applicazione, es. '1002'

// Programmi espliciti: base64, 0x… o sorgente TEAL
await algorand.deploy(notarizer, { approval: approvalBase64, clear: clearBase64 }, ['CERTIFIE']);
Esempio
var notarizer = await File.ReadAllTextAsync("Notarizer.arc56.json");

// Gli argomenti vanno al metodo di creazione (qui create(string)void).
// Value finanzia il conto dell'applicazione dopo la creazione, es. per le box che salverà: 0,2 ALGO in microAlgo.
var deployed = await algorand.DeployAsync(notarizer, "", new object[] { "CERTIFIE" },
    options: new TransactionOptions { Value = 200_000 });
var appId = deployed.Tx!.ContractAddress!; // ID dell'applicazione, es. "1002"

// Programmi espliciti: base64, 0x… o sorgente TEAL
await algorand.DeployAsync(notarizer, new AvmPrograms { Approval = approvalBase64, Clear = clearBase64 }, new object[] { "CERTIFIE" });

Il metodo di creazione è quello che ARC-56 indica con l’azione NoOp in actions.create, oppure, nelle descrizioni senza azioni, quello chiamato create o createApplication. Lo schema dello stato e le pagine extra si ricavano dalla descrizione e dalla dimensione dei programmi.

Nota

La compilazione della sorgente TEAL richiede un nodo con EnableDeveloperAPI (attivo su LocalNet). Con i nodi pubblici usa una descrizione ARC-56 con byteCode o passa i programmi già compilati.

Notarizzazione

Come sulle reti EVM, mint chiama mint(address,string,string,string)void con hash, algoritmo e metadati. L’indirizzo del contratto è l’ID dell’applicazione; il primo argomento è il conto dell’applicazione, come l’indirizzo del contratto su EVM.

Esempio
const result = await algorand.mint(notarizer, appId, {
  hash: { data: 'e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855', algorithm: 'sha2' },
  metadata: 'ipfs://bafy...',
});

result.tx?.transactionHash; // ID della transazione Algorand
result.tx?.blockNumber;     // round di conferma
result.nativeFee;           // { amount: '1000', symbol: 'ALGO', decimals: '6' }: commissione in microAlgo
Esempio
var result = await algorand.MintAsync(notarizer, appId, new NotarizationDocument
{
    Hash = new NotarizationHash { Data = hash, Algorithm = "sha2" },
    Metadata = "ipfs://bafy...",
});

Console.WriteLine(result.Tx!.TransactionHash); // ID della transazione Algorand
Console.WriteLine(result.NativeFee!.Amount);   // "1000": commissione in microAlgo

Applicazioni e metodi ARC-4

getContract(abi, appId) restituisce un Web3Contract con gli stessi metodi delle reti EVM. I metodi readonly sono letture, quelli con un argomento pay sono payable, gli altri sono scritture.

Esempio
const app = algorand.getContract(notarizer, appId);
app.methods.map(method => method.signature); // ['create(string)void', 'mint(address,string,string,string)void', 'label()string', …]

await app.call('label');                             // 'CERTIFIE': simulazione gratuita
await app.call('metadata', { hash: 'e3b0…' });       // ['e3b0…', 'sha2', 'ipfs://bafy...']: le tuple diventano array

const token = algorand.getContract(tokenArc56, tokenAppId); // un'applicazione ARC-200
await token.call('arc200_transfer', { to: 'ALGO…', value: '1000' }); // transazione, restituita quando è confermata
await token.call('deposit', { note: 'grazie' }, { value: '100000' }); // payable: 0,1 ALGO pagati all'applicazione
Esempio
var app = algorand.GetContract(notarizer, appId);
var label = await app.CallAsync("label");                          // "CERTIFIE": simulazione gratuita
var metadata = await app.CallAsync("metadata", new { hash = "e3b0…" }); // ["e3b0…", "sha2", "ipfs://bafy..."]

var token = algorand.GetContract(tokenArc56, tokenAppId); // un'applicazione ARC-200
await token.CallAsync("arc200_transfer", new { to = "ALGO…", value = "1000" }); // transazione confermata
await token.SendAsync("deposit", new { note = "grazie" }, new TransactionOptions { Value = 100_000 }); // payable

Prima di ogni scrittura la libreria simula il gruppo di transazioni sul nodo. Così trova da sola conti, applicazioni, asset e box che l’applicazione legge, calcola la commissione delle transazioni interne e, se l’applicazione rifiuterebbe la chiamata, restituisce TRANSACTION_REVERTED senza inviare né pagare nulla, con il messaggio di errore della descrizione ARC-56 quando c’è. Le letture sono simulazioni senza commissione, quindi non richiedono un conto finanziato.

Token e NFT

Su Algorand un token può esistere senza contratto: è un Algorand Standard Asset (ASA), creato con createToken e letto con getTokenInfo. Un NFT è un ASA con totalSupply 1 e decimals 0. Il creatore ne resta il gestore.

Esempio
const coin = await algorand.createToken({ name: 'Certifie Coin', symbol: 'CERT', totalSupply: '1000000000', decimals: 2 });
coin.tokenId; // ID dell'asset, es. '1005'

const nft = await algorand.createToken({
  name: 'Certificato #1', symbol: 'CERT1', totalSupply: 1,
  uri: 'ipfs://bafy...#arc3',                // ARC-3
  metadataHash: '0x' + sha256OfMetadataJson, // 32 byte, opzionale
});

await algorand.getTokenInfo(coin.tokenId);
// { standard: 'ASA', address: '1005', name: 'Certifie Coin', symbol: 'CERT', decimals: '2', totalSupply: '1000000000', creator: 'ALGO…' }
Esempio
var coin = await algorand.CreateTokenAsync(new TokenDefinition { Name = "Certifie Coin", Symbol = "CERT", TotalSupply = 1_000_000_000, Decimals = 2 });
Console.WriteLine(coin.TokenId); // ID dell'asset, es. "1005"

var info = await algorand.GetTokenInfoAsync(coin.TokenId); // Standard "ASA", Name, Symbol, Decimals, TotalSupply, TokenURI, Creator
CampoLimite su Algorand
nameAl massimo 32 byte
symbolUnit name, al massimo 8 byte
totalSupplyDa 1 a 264 − 1 unità minime
decimalsDa 0 a 19, default 0
uriAl massimo 96 byte
metadataHash32 byte in esadecimale 0x…

I token gestiti da un’applicazione funzionano come i contratti ERC: standards riconosce ARC-200 (fungibili), ARC-72 (NFT) e ARC-73, getTokenInfo legge nome, simbolo, decimali e offerta, e mintNft usa arc72_mint (oppure safeMint, mint, mintTo). Gli ID dei nuovi token arrivano dagli eventi arc72_Transfer o dagli ASA creati dalle transazioni interne dell’applicazione.

Esempio
const collection = algorand.getContract(nftArc56, nftAppId);
collection.standards; // ['ARC-72', 'ARC-72 Enumeration', 'ARC-72 Management', 'ARC-73']
const minted = await collection.mintNft({ to: 'ALGO…', uri: 'ipfs://bafy...' }); // arc72_mint(address,string)
await collection.getTokenInfo(minted.tokenIds[0]); // { standard: 'ARC-72', tokenId, totalSupply, owner, tokenURI }
Esempio
var collection = algorand.GetContract(nftArc56, nftAppId);
var minted = await collection.MintNftAsync(new { to = "ALGO…", uri = "ipfs://bafy..." }); // arc72_mint(address,string)
var nft = await collection.GetTokenInfoAsync(minted.TokenIds[0]); // Standard "ARC-72", Owner, TokenURI

Ricevute e commissioni

Le transazioni hanno la stessa forma JSON delle reti EVM; i campi che su Algorand non esistono sono zero o vuoti.

tx.blockNumber, tx.blockHashRound di conferma e hash del suo blocco
tx.contractAddressID dell’applicazione creata, dopo deploy
tx.statusSempre '1': Algorand non registra transazioni fallite, che restituiscono invece TRANSACTION_REVERTED prima dell’invio
tx.logsLog dell’applicazione: data in esadecimale, address è il conto dell’applicazione
gasUsed, cumulativeGasUsed'0'
